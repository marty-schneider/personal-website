SECURITY & HARDENING

Living case study of applied defensive engineering on a personal public system • Last reviewed: 2026-05-25
OVERVIEW

This document provides a transparent, technical view of the security posture and hardening decisions applied to martyschneider.com (and the associated private learning vault at learning.martyschneider.com).

The goal is not to claim the site is "secure" in any absolute sense, but to demonstrate how DevSecOps and defensive engineering practices are applied to a low-value, high-visibility personal system that I actually control and expose publicly.

SYSTEMS IN SCOPE
  • Public static portfolio (index.html + assets) — currently GitHub Pages fronted by Cloudflare
  • Planned migration to native Cloudflare Pages (where _headers becomes authoritative)
  • Nightly CVE intelligence pipeline (.github/workflows/ + scripts/update_nvd_feed.py)
  • Private learning vault (private-vault/ — Cloudflare Worker + R2 behind Cloudflare Access)
KEY HARDENING CONTROLS (AS OF 2026-05)

THREAT MODEL (SIMPLIFIED)

Assets: Public professional reputation, contact email, private learning content (low volume, low sensitivity).

Primary threats considered:

  • Supply chain compromise of third-party resources
  • Clickjacking / UI redress
  • Information disclosure via misconfigured headers or caching
  • Abuse of the private vault (unauthorized access to learning materials)
  • Abuse of the public NVD feed pipeline (repo write via compromised workflow)

This is a personal portfolio, not a high-value target. Controls are proportionate.

RESIDUAL RISKS & ACCEPTANCE
  • Monolithic index.html with heavy inline styles/scripts → CSP is difficult without breaking the current experience. Accepted for now.
  • GitHub Actions still has repository write via the NVD workflow. Mitigated by minimal permissions + only touching one file.
  • GitHub Pages origin still serves some traffic. Being removed during Cloudflare Pages migration.
ONGOING PRACTICES
  • Automated CVE intelligence feed (EPSS + CISA KEV + relevance) as a living security sensor.
  • Private vault content never committed to this public repo.
  • CI pipeline with workflow security (zizmor), secret scanning, dependency review, and header validation — results published to data/pipeline-status.json and visible in the terminal.
  • Regular review of this document (target: quarterly or on significant changes).
This page is intentionally lightweight and self-contained. It will be updated as the Cloudflare Pages migration and additional hardening work (see Initiatives #1–3) progresses.
